# 大课程分批与中断续做

`scripts/session.py` 是本地进度与文件完整性工具，不调用模型、不联网，也不生成讲义。宿主模型负责理解课件、写 Markdown、求解与复核题目。脚本只写 `_session/` 中的进度元数据，不修改、删除或覆盖课程原文件和学习内容。

## 1. 新建一次，保存学习要求

输入与输出必须是互不嵌套的路径。输出使用新目录或空目录；不能把已有笔记目录初始化为新复习包。

```bash
python scripts/session.py init "课程资料" --out "复习包" --mode both --papers 3
```

- `--mode`：`detailed`（详细）、`concise`（精简）、`both`（两种）。新会话默认 `detailed`。
- `--papers`：正整数，新会话默认 3 套。套数不是对真实考试的推断；资料不足时先向用户解释，再调整计划。
- 模式、套数、全部输入文件的 SHA-256、章节检查点和已完成阶段保存到 `_session/state.json`。再次运行相同 `init` 不重置进度；不传模式/套数时沿用原设置。显式传入不同设置会拒绝操作，需要另建输出目录。
- 另外先写 `_work/session-context.md`，保存课程名称、语言、考试范围、用户要求、已知题型/时长、尚未提供的信息和拆章计划；恢复时先读此文件。它是宿主模型写的 Markdown，不是脚本自动生成的。待内容稳定并复核后，可作为 `inventory` 的一个检查点登记。最终 `00-开始阅读.md` 继续记录交付信息，不要为了更新交付状态覆盖已经登记的上下文文件。

初始化后再提取。提取脚本仍要求 `_sources` 不存在：

```bash
python scripts/extract_sources.py "课程资料" --out "复习包/_sources"
```

阅读提取状态与警告，完成可用的视觉核对；把未解决项写到独立的待核对记录。只有在本阶段实际工作已处理、失败/未核对材料明确记录后才登记阶段完成。检查点本身不代表材料已完整读取。

```bash
python scripts/session.py record "复习包" --phase extract --key sources-v1 --file _sources/manifest.json --file _sources/sources.md --complete-phase
```

如提取失败或中断，先检查已经存在的 `_sources`，不要重跑到原路径。保留该目录，必要时用新路径重新提取，再按实际结果登记。

## 2. 按章记录，最后显式完成阶段

推荐阶段：

1. `extract`：提取来源与记录失败、视觉核对情况。
2. `inventory`：章节/知识点清单、来源对应和学习要求。
3. `notes`：按章节写详细/精简内容，再合并成最终讲义。
4. `practice`：逐套练习卷及题目蓝图。
5. `answers`：独立答案、求解和评分点。
6. `audit`：结构/引用检查、逐题复核、覆盖与待核对记录及最终交付。

各阶段可以有多个检查点，`--key` 使用稳定的章节/批次标识（1–80 个 ASCII 字母、数字、点、下划线或连字符，以字母或数字开头）。只登记**实际存在、非空、已经人工复核**的文件；路径相对复习包，目录分隔符统一用 `/`。中文文件名可用。`--file` 可以重复。

```bash
python scripts/session.py record "复习包" --phase inventory --key context --file _work/session-context.md
python scripts/session.py record "复习包" --phase notes --key ch01-detailed --file _work/详细-第01章.md
python scripts/session.py record "复习包" --phase notes --key ch02-detailed --file _work/详细-第02章.md
```

登记一章**不会**自动完成 `notes`。每次恢复先读已登记清单，继续未完成章节；先写新文件，再登记。两种模式都要时，应分别完成两版所需章节并检查合并内容。

合并讲义写到尚不存在的最终路径。核对知识清单中所有应纳入的章、公式、例题和待核对项后，才显式完成阶段，例如：

```bash
python scripts/session.py record "复习包" --phase notes --key merged-v1 --file 02-详细复习.md --file 02-精简复习.md --complete-phase
```

登记进度前会再次核对来源和输出；若这次核对发现新变化，不保存检查点或阶段完成声明。核对仍只是当时的快照，不能阻止其他程序在之后修改文件。

`--complete-phase` 是操作者明确作出的完成声明。脚本验证文件存在与哈希，不会替代知识清单核对，不会推断章节覆盖率，也不会判定答案正确。允许分批记录不同阶段，`next_phase` 仅提示按推荐顺序最早尚未完成的阶段。

已经登记的文件视为本次会话的固定版本。发现需要修正时，不在原路径直接改写：先将修正写成新文件（例如 `_work/详细-第01章-v2.md`），用新 key 登记，在后续合并稿/核对说明中指出替代关系。已完成阶段不能静默重开；需实质调整计划、最终文件或已完成内容时，新建一个输出目录，保留旧包和用户笔记。

## 3. 每次恢复先检查

```bash
python scripts/session.py status "复习包"
```

`status` 只读，不保存新基线，不清理文件。主要输出：

- `settings`：原模式和套数。
- `checkpoints`：已登记的阶段、key 和文件。
- `completed_phases`、`pending_phases`、`next_phase`：明确完成的阶段和续做位置。
- `input_changes`：新增、删除或字节变化的输入文件。
- `output_changes`：登记过的文件被修改或删除。
- `unrecorded_files`：存在但未登记的内容，可能是中断时的半成品，也可能是用户笔记。
- `needs_review`、`errors`、`resume_instructions`：需检查的问题和下一步。

未登记文件不等于可以覆盖。逐个查看：完整且复核通过的文件可登记；不完整或用户自行添加的文件保留原样，换一个新文件名继续。不要为了让检查通过而先删除这些文件。

相同 phase/key、相同文件和哈希的 `record` 可重复执行，不增加重复记录、不改动状态文件。相同 key 不能换一组文件。完成声明可在复核之后对同一检查点追加一次；已经完成时重复声明仍是无操作。

## 4. 用户已加笔记时，保留编辑继续新章节

默认情况下，任何输入变化或已登记输出变化都会阻止 `record`。不要把用户编辑自动更新成新哈希，也不要用旧稿覆盖用户修改。

若**输入完全未变、没有已登记文件丢失、所有路径均可核验，只有输出被用户修改**，可以明确选择保留这些编辑，继续尚未完成的新内容：

```bash
python scripts/session.py record "复习包" --phase notes --key ch03-detailed --file _work/详细-第03章.md --preserve-edits
```

此选项只登记全新 key 下的全新文件路径（相同已成功命令可重复）。原检查点、原哈希和改过的文件内容都保留；修改冲突会持续显示，不能声称整个包校验通过。冲突存在时，任何阶段都不能加 `--complete-phase`。输入变化、文件丢失、链接路径或读取错误都不能用此选项绕过。

`record --preserve-edits` 即使成功保存新检查点，仍会返回 `ok: false` 和退出码 2，并同时显示 `recorded: true` 与 `preserved_output_edits`。这表示新进度已存好，但已有编辑仍需处理；不要因退出码非零反复生成文件。

最终需要一个一致、可交付的修订包时，使用新输出目录，并明确保留/迁移用户笔记及修正记录。脚本不会自动合并或消除冲突。只有用户明确同意时，才考虑由用户恢复旧字节；脚本没有“强制覆盖”或“重设基线”选项。

## 5. 中断、路径与退出码

- 状态使用同目录临时文件、文件 `fsync` 和原子替换提交；支持时也同步目录。写入中断后，主状态应是旧版或新版完整 JSON，而不是半份 JSON。写锁防止两个写命令相互覆盖，进程退出后由系统释放。
- 极端中断可能留下 `_session/.state-*.tmp`。它们不是成功检查点，不自动恢复或覆盖主状态；正常恢复只读取 `state.json`。不要修改或拷贝临时文件冒充进度。
- 初次初始化中断且只留下内部临时文件时，可重复 `init`。若已有学习内容但尚无有效状态，不会自动接管它；保留目录并另建新输出。
- 主状态损坏或无法读取时停止，保留原文件并另开输出目录。不要手工删状态再初始化，以免把修改与遗漏隐藏。
- 输入/输出根本身及内容树中的符号链接、Windows junction/reparse point、非普通文件和越界路径被拒绝。macOS `/tmp`、`/var` 等正常祖先别名会在选择根路径时规范化。
- 输入目录中的普通文件都纳入指纹，只有 `~$` 开头的 Word 锁文件及 `.DS_Store`、`Thumbs.db`、`desktop.ini`（不区分大小写）被忽略；输入单文件时只跟踪该文件。输出扫描不忽略这些名称，以免隐藏已有内容。不要把输出放到输入目录内，也不要把输入放到输出目录内。移动整个复习包或更换输入根需要新会话，不静默接受旧绝对路径。
- `status`/`init`/`record` 退出码：`0` 为文件完整性检查无冲突（仍需查看未登记文件及语义质量）；`2` 为发现完整性冲突；`1` 为拒绝操作、状态异常或文件系统错误。命令参数错误由 argparse 返回 `2`，此时没有 JSON 成功结果。写入后发生系统错误时，先运行 `status` 确认是否已提交，再决定重试。
- 此工具的保证是正常本地文件系统上的意外中断恢复与不覆盖内容，不是文件备份，也不承诺防御另一个恶意进程同时替换目录或不遵守原子语义的网络磁盘。不要并行编辑同一内容文件。
- 本机测试覆盖 Linux 上真实子进程中断、锁竞争、重复命令、改动检测和路径边界。macOS/Windows 有对应实现和跨平台测试设计；没有实际运行对应 CI/系统前，不宣称已完成那两个系统的实测。
